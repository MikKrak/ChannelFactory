# План работ ChannelFactory

Этот документ фиксирует ближайшие задачи и точку возобновления после паузы. Концепция — CONCEPT.md, проверенное состояние — STATUS.md.

## 1. Предоставить локальному серверу внешний HTTPS-доступ

**Статус: запланировано, ещё не выполнялось.**

**Цель:** оставить ChannelFactory на Mac, но дать Telegram возможность доставлять входящие сообщения через webhook непосредственно в локальный FastAPI, без ручного вызова getUpdates и без VPS.

### План действий

1. Убедиться, что локальный FastAPI запускается и доступен на localhost:8000; определить маршрут для Telegram webhook.
2. Настроить Cloudflare Tunnel (на первом этапе допустим временный публичный HTTPS-адрес, без собственного домена и открытия портов MikroTik).
3. Реализовать приём Telegram Update по HTTPS в FastAPI: проверять секретный заголовок webhook, не публиковать токены и ключи; сохранять входящие сообщения и защищаться от повторной обработки update_id.
4. Зарегистрировать webhook Telegram на выданный HTTPS-адрес, учитывая, что одновременно использовать getUpdates и активный webhook нельзя.
5. Повторить проверенный сценарий Direct Messages: Светлана отправляет вопрос в Direct канала; бот получает событие с chat.id=-2074286946874 и direct_messages_topic.topic_id=8061146791. Убедиться, что сообщение автоматически поступает в ChannelFactory.
6. Отдельно проверить отправку ответа ботом в нужный Direct-диалог через Bot API; не считать её реализованной до успешного теста.
7. Зафиксировать результат и команды запуска/остановки в документации; вынести публичный URL и секреты в конфигурацию. Для временного туннеля предусмотреть обновление адреса webhook после перезапуска.

**Ограничение:** Mac и туннель работают только во время разработки; ночью сервис может быть выключен. Telegram не гарантирует бессрочное хранение ожидающих обновлений (максимум 24 часа). DigitalOcean и круглосуточный хостинг пока не требуются.

## 2. Связать ChatGPT, существующий GitHub и локальную разработку

**Статус: запланировано, ещё не выполнялось.**

**Цель:** существующий репозиторий https://github.com/MikKrak/ChannelFactory становится единым источником исходников и документации. Нынешняя рабочая папка ChannelFactory остаётся на Mac, приложение продолжает работать локально через Uvicorn/FastAPI. Ассистент редактирует код через GitHub; владелец синхронизирует его через GitHub Desktop. Work/Codex необязательны для обычных правок, но полезны для автономного запуска и тестирования.

### Исходная ситуация

- На Mac уже есть рабочая папка ChannelFactory с исходниками Python и интерфейсом. По словам владельца, она не связана ни с каким Git-репозиторием.
- GitHub Desktop уже установлен.
- Удалённый репозиторий MikKrak/ChannelFactory уже содержит README.md, CONCEPT.md, STATUS.md, DEVELOPMENT.md, AGENTS.md и другие документы. Новый репозиторий не создавать.
- Предполагаемые файлы прототипа: main.py, database.py, source.py, extractor.py, editor.py, telegram.py, templates/index.html. Фактический состав уточнить при настройке.
- Mac остаётся локальным сервером; GitHub хранит код, но не исполняет FastAPI.

### План действий

1. Создать проект ChatGPT «ChannelFactory» и перенести туда текущий чат. При необходимости создать служебные чаты для архитектуры, разработки, интерфейса и эксплуатации. Принятые решения сохранять в GitHub, а не только в чатах.
2. Сделать резервную копию существующей локальной папки ChannelFactory; оригинал не перемещать.
3. Проверить локальные файлы и подготовить .gitignore. Не публиковать .env, токены Telegram, ключи Supabase, .venv, временные файлы и другие секреты. Проверить состав первого коммита.
4. Через GitHub Desktop безопасно объединить исходники с уже существующим удалённым репозиторием. ВАЖНО: удалённая ветка main содержит документацию, а локальная папка не имеет общей Git-истории. Не нажимать Publish repository, не делать force push и не выполнять слепое объединение. Выбрать способ после проверки локального состояния: например, временно клонировать существующий репозиторий, аккуратно добавить исходники и затем настроить постоянную локальную рабочую папку.
5. Добавить исходный код в MikKrak/ChannelFactory, сохранив документацию. Проверить структуру, requirements.txt, инструкции запуска и отсутствие секретов.
6. Проверить двустороннюю синхронизацию: изменения ассистента в GitHub → Fetch/Pull в GitHub Desktop на Mac; изменения владельца на Mac → Commit/Push. Перед Pull проверять незакоммиченные изменения и возможные конфликты.
7. Проверить локальный запуск и ключевые сценарии в браузере. При необходимости запускать uvicorn main:app --reload (если структура приложения соответствует этой команде). Зависимости устанавливать отдельно; миграции Supabase выполнять отдельно.
8. Позднее настроить автоматические проверки (например, GitHub Actions), а затем облачный хостинг FastAPI из GitHub. Обсуждались Railway/Render, но выбор не сделан. GitHub Pages публикует статические сайты, а Python/FastAPI не запускает.

### Повседневный цикл

Обсуждаем изменение в ChatGPT → ассистент правит файлы через GitHub и фиксирует коммит → владелец делает Fetch/Pull в GitHub Desktop → проверяет на локальном Uvicorn и сообщает результат. Если владелец меняет файлы локально, он делает Commit/Push, после чего ассистент видит новую версию. Git синхронизирует код и документацию, но не данные Supabase, секреты .env, установленные Python-пакеты или состояние сервера.

### Точка возобновления

**Следующее действие после этапа внешнего доступа:** посмотреть в GitHub Desktop состояние существующей локальной папки ChannelFactory и проверить наличие .git, .gitignore, .env и состав исходников. Затем выбрать безопасную процедуру соединения с существующим удалённым репозиторием. Пользователь пока откладывает настройку ради других вопросов.
