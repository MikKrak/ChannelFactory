# План работ ChannelFactory

Этот документ фиксирует ближайшие задачи и точку возобновления после паузы. Концепция — CONCEPT.md, проверенное состояние — STATUS.md.

**Принятая архитектура разработки:** Mac (локальная разработка и длительные задачи Engine) + GitHub (исходники) + Vercel Hobby (тестовые FastAPI/Studio и Telegram webhook) + Supabase (общие данные). Уже есть опыт с действующими проектами HTP на Vercel, связанными с GitHub и Supabase. Cloudflare Tunnel, Railway и VPS сейчас не нужны; будущий производственный хостинг не выбран.

## 1. Связать ChatGPT, существующий GitHub и локальную разработку

**Статус: запланировано, ещё не выполнялось.**

**Цель:** существующий репозиторий https://github.com/MikKrak/ChannelFactory становится единым источником исходников и документации. Нынешняя рабочая папка ChannelFactory остаётся на Mac, приложение продолжает работать локально через Uvicorn/FastAPI; после синхронизации исходников тестовая веб-версия будет развёрнута на Vercel Hobby. Ассистент редактирует код через GitHub; владелец синхронизирует его через GitHub Desktop. Work/Codex необязательны для обычных правок, но полезны для автономного запуска и тестирования.

### Исходная ситуация

- На Mac уже есть рабочая папка ChannelFactory с исходниками Python и интерфейсом. По словам владельца, она не связана ни с каким Git-репозиторием.
- GitHub Desktop уже установлен.
- Удалённый репозиторий MikKrak/ChannelFactory уже содержит README.md, CONCEPT.md, STATUS.md, DEVELOPMENT.md, AGENTS.md и другие документы. Новый репозиторий не создавать.
- Предполагаемые файлы прототипа: main.py, database.py, source.py, extractor.py, editor.py, telegram.py, templates/index.html. Фактический состав уточнить при настройке.
- Mac остаётся локальным сервером; GitHub хранит код, но не исполняет FastAPI.

### План действий

1. Создать проект ChatGPT «ChannelFactory» и перенести туда текущий чат. При необходимости создать служебные чаты для архитектуры, разработки, интерфейса и эксплуатации. Принятые решения сохранять в GitHub, а не только в чатах.
2. Сделать резервную копию существующей локальной папки ChannelFactory; оригинал не перемещать.
3. Проверить локальные файлы и подготовить .gitignore. Не публиковать .env, токены Telegram, ключи Supabase, .venv, временные файлы и другие секреты. Проверить состав первого коммита.
4. Через GitHub Desktop безопасно объединить исходники с уже существующим удалённым репозиторием. ВАЖНО: удалённая ветка main содержит документацию, а локальная папка не имеет общей Git-истории. Не нажимать Publish repository, не делать force push и не выполнять слепое объединение. Выбрать способ после проверки локального состояния: например, временно клонировать существующий репозиторий, аккуратно добавить исходники и затем настроить постоянную локальную рабочую папку.
5. Добавить исходный код в MikKrak/ChannelFactory, сохранив документацию. Проверить структуру, requirements.txt, инструкции запуска и отсутствие секретов.
6. Проверить двустороннюю синхронизацию: изменения ассистента в GitHub → Fetch/Pull в GitHub Desktop на Mac; изменения владельца на Mac → Commit/Push. Перед Pull проверять незакоммиченные изменения и возможные конфликты.
7. Проверить локальный запуск и ключевые сценарии в браузере. При необходимости запускать uvicorn main:app --reload (если структура приложения соответствует этой команде). Зависимости устанавливать отдельно; миграции Supabase выполнять отдельно.
8. Подготовить развёртывание FastAPI на Vercel Hobby из GitHub (следующий этап), сохранив возможность локального запуска. Позднее настроить автоматические проверки, например GitHub Actions.

### Повседневный цикл

Обсуждаем изменение в ChatGPT → ассистент правит файлы через GitHub и фиксирует коммит → владелец делает Fetch/Pull в GitHub Desktop → проверяет на локальном Uvicorn и сообщает результат. Если владелец меняет файлы локально, он делает Commit/Push, после чего ассистент видит новую версию. Git синхронизирует код и документацию, но не данные Supabase, секреты .env, установленные Python-пакеты или состояние сервера.

### Точка возобновления

**Следующее действие:** посмотреть в GitHub Desktop состояние существующей локальной папки ChannelFactory и проверить наличие .git, .gitignore, .env и состав исходников. Затем выбрать безопасную процедуру соединения с существующим удалённым репозиторием. Пользователь пока откладывает настройку ради других вопросов.

2. Создать отдельный проект ChannelFactory в Vercel, подключить существующий репозиторий MikKrak/ChannelFactory.
3. Настроить переменные окружения и подключение к Supabase для нового проекта; не переносить секреты в GitHub или клиентский JavaScript.
4. Проверить публичный HTTPS-адрес, Studio, чтение и запись тестовых данных; предусмотреть защиту редакторских маршрутов от постороннего доступа.
5. Проверить цикл GitHub → автоматическое развёртывание Vercel. Сохранить локальный запуск FastAPI на Mac для отладки.
6. Для Engine оставить запуск длительных задач на Mac по необходимости; предусмотреть согласованную работу с Supabase и защиту от дублирования заданий.

2. Зарегистрировать постоянный HTTPS-адрес Vercel как webhook бота @cccp_service_bot; учесть несовместимость активного webhook с getUpdates.

4. Отдельно проверить отправку ответа ботом в Direct-диалог через Telegram Bot API; до успешного теста не считать её реализованной.
5. Задокументировать настройки, диагностику и порядок отключения webhook. Длительную обработку не выполнять внутри короткого HTTP-запроса.

**Ограничения:** Vercel Hobby используется на некоммерческом этапе и в пределах действующих условий тарифа. Производственный хостинг и круглосуточный Engine не планируются на данном этапе.
