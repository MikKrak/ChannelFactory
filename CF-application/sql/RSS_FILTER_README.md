# Мастер RSS-фильтра — CF-02C-011

Рабочая миграция **20261031135924 cf_rss_project_filter применена 31.10.2026** после отдельного разрешения владельца. Прежние данные 13 таблиц, включая 99 проектных связей, сохранены. Рабочий мастер включён в отдельном локальном кабинете http://127.0.0.1:8004/studio . Правила в базе пока пусты, импорт не запускался. Демо на 8003 остаётся отдельным приложением.

## Алгоритм

Правила относятся к связи источник ↔ проект. Рубрики сравниваются как точные названия без учёта регистра/ё; они не объединяются в иерархию. Включения внутри группы объединены ИЛИ, между группами рубрик/слов пользователь выбирает И либо ИЛИ. Пустая группа не ограничивает отбор, обе пустые допускают любую тему. Найденное исключение всегда сильнее включения.

Слова/фразы ищутся в заголовке и очищенном RSS-описании по границам слов, фраза — последовательность соседних слов. Не ищем по URL, автору и полному тексту страницы. «ё»/«е» и регистр не различаются. Дополнительный флаг использует ограниченный список русских окончаний: это приближение, без словаря/понимания смысла/синонимов, с возможными ошибками. Флаг можно снять для точных словоформ. Нет LLM, внешних AI API, моделей, новых платных сервисов и новых зависимостей.

Когда нужных для проверки данных не хватает, решение «сомнительно». Например, нет рубрик при фильтре по рубрикам или нет совпадения в заголовке и отсутствует описание для проверки слов. Если заведомо не выполнено обязательное условие, материал отклоняется; если заведомо сработало исключение, он также отклоняется. Само по себе наличие темы не является оценкой качества публикации. Для каждого решения показывается причина, включая поле найденного слова.

Максимум 50 условий в каждом поле, условие до 100 символов, фраза до 12 слов. Не поддерживаются регулярные выражения и пользовательский код. Проверка ограничена выборкой до 200 уже загруженных материалов или первой страницей RSS (перед записью импорта максимум 200). Распределение рубрик относится к выборке, а не ко всему архиву сайта. Выборка мастера живёт в памяти до 30 минут, не более 20 выборок на процесс; при перезапуске нужно анализировать заново.

## Схема и будущий штатный импорт

- Добавляет cf_project_sources.filter_rules и filter_revision. Сохранение проверяет ожидаемую версию и меняет только конфигурацию. Допуск отбора/правила защищены увеличением версии при изменении.
- Новая cf_material_filter_results хранит решение, причины и версию для каждого нового материала/проекта. Не переписывает старые решения при изменении правил. Тексты переписки сюда не попадают. RLS включён, клиентским ролям доступ закрыт, новые функции SECURITY INVOKER с пустым search_path и без публичного EXECUTE.
- `cf_filter_import` сохраняет всю новую общую выборку, решения и ссылки только принятых материалов одной транзакцией. Перед записью проверяет версии всех активных конфигураций и полноту решений. При смене настроек/ошибке ничего не сохраняет. При повторе известных URL не переписывает материал и не отбирает его заново.
- Автоматически участвуют только подключённые источники с enabled=true, сохранёнными правилами и auto_select=true. Без этого материал только попадает в общую библиотеку.
- Старый массовый cf_library_select не обходит структурированный фильтр. Ручной выбор одной статьи остаётся отдельным явным действием. Старый cf_library_import запрещает импорт в обход активной автоматической конфигурации; нужно использовать новый процесс с включённым флагом.
- Старые 99 связей не пересматриваются ни при сохранении правил, ни при предпросмотре, ни при повторе известных URL. Автоматический отбор касается только новых URL. Обогащение метаданных уже известных статей и массовый пересмотр старой библиотеки требуют отдельного решения.
- «Сомнительно» доступно отдельным просмотром, не включается в проект автоматически и исключается из предварительного списка очистки. Отклонённые остаются в общей библиотеке. Реального удаления в приложении нет.

## Безопасная демонстрация до разрешения

Из каталога CF-application:

`CF_RSS_FILTER_DEMO=1 CF_RSS_FILTER_ENABLED=0 .venv/bin/python -m uvicorn rss_filter_demo:app --host 127.0.0.1 --port 8003`

Демо читает только публичные RSS-данные из `/private/tmp/cf-rss-filter-011-sample.json` и снимок публичных полей прежних материалов `/private/tmp/cf-rss-filter-011-stored.json`. Это не копия всей базы и не переписка. В интерфейсе явно указан тестовый режим, правила сохраняются только в памяти. Маршрутов рабочего импорта, публикации, ответа и изменения связей у этого сервера нет. После перезапуска сохранённые тестовые правила сбрасываются.

Открыть http://127.0.0.1:8003/studio . Нажать «Анализировать RSS-снимок», выбрать рубрики кнопками включения/исключения либо ввести слова, нажать «Проверить фильтр». Для сохранения — отдельная галочка и «Сохранить фильтр». После изменения правил нужно снова проверить их; сохранить другую непроверенную конфигурацию нельзя. Для проверки неполных старых данных есть «Взять уже загруженные материалы».

## Порядок подключения (выполнен до шага 3 включительно)

1. Повторно сверить рабочую схему/данные, сохранить закрытую резервную копию конфигурации/ссылок и контрольные суммы.
2. Применить `rss_filter.sql` через Supabase-плагин единственной согласованной миграцией. Проверить сохранность прежних полей и 99 ссылок, закрытый клиентский доступ. Не удалять ничего.
3. Запустить новый локальный процесс `main:app` с CF_LIBRARY_ENABLED=1 и CF_RSS_FILTER_ENABLED=1; сохранить остальные разрешения отправки выключенными. .env не менять. Старые процессы автоматически не обновляются.
4. Мастер доступен из RSS-карточки и по `/studio/library/sources/{source_id}/filter?project={code}`. Реальные проекты берутся из cf_projects, настройки только для существующего подключения. Сохранение фильтра и его содержания владелец подтверждает отдельно; примерные демо-правила не переносить в рабочую конфигурацию автоматически.
5. Реальный импорт и изменение связей — отдельное разрешение, не часть простого включения мастера. Публикации/ответы/удаление этим не разрешаются.
