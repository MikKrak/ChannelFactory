# Версия 2 настройки отбора — CF-02C-012

**Рабочая миграция 20261031195915 cf_filter_config_v2 применена 31.10.2026** после поручения владельца завершить задание в полном приложении. Рабочий кабинет: http://127.0.0.1:8010/studio . `rss_filter_config.sql`: добавляет поддержку версии 2 в валидатор и защищает сохранение/импорт от старых процессов. Таблицы, прежние правила и проектные ссылки не переписывает; существующий `cf_filter_save` с блокировкой и проверкой версии остаётся единственной операцией записи. Импорт версии 2 требует явного подтверждения версии алгоритма в плане; старый процесс без него получает отказ до записи. Перезаписать версию 2 правилами версии 1 нельзя. Клиентские роли закрыты. Новый интерфейс подключён к рабочему хранению; демонстрационные правила не переносились. Все 14 таблиц совпали по контрольным суммам до/после миграции и после проверки интерфейса.

## Правила

- В новом подключении фильтр выключен, все рубрики включены. Выключение сохраняет конфигурацию. При рабочем импорте с сохранённой конфигурацией выключенный фильтр не ограничивает тему: все **новые** материалы участвуют в отборе, если само подключение источника допущено (`cf_project_sources.enabled`). Сохранение и переключение не запускают импорт и не перепривязывают прежние статьи.
- Рубрика включена либо исключена. `category_default` задаёт состояние рубрик без явного исключения, в том числе новых. Построчная команда меняет только одну рубрику; массовая меняет всё явно. Список и поля отражают друг друга.
- Одной включённой рубрики достаточно для рубричного основания, даже при других исключённых. Исключённая рубрика — отсутствие основания, не запрет.
- Включающие фразы сочетаются с рубриками через И/ИЛИ. Если рубрик нет, совпадение включающей фразы может подтвердить тему независимо от И. Без подтверждения темы — сомнительно. Известное отсутствие нужного слова в полном описании — отказ. Исключающие фразы запрещают; если описания нет, проверка исключающих фраз неполна — сомнительно.
- «Проверить отбор» испытывает правила даже при выключенном фильтре и явно это сообщает. Рабочий импорт использует сохранённое состояние выключателя.
- Первоначальное предложение основано только на совпадении слов названия/описания проекта и рубрик. Без ИИ/понимания смысла. Служебные слова не считаются основанием. Нет совпадений — нет предложения. Нажатие «Использовать предложение» — явный выбор включать указанные рубрики, исключать остальные; выключатель не меняется. Само чтение выборки ничего не сохраняет.
- Версия 1 продолжает классифицироваться прежним алгоритмом. Вход в новую настройку не преобразует её. Переход требует явного «Создать новый вариант»; пользователь задаёт новую конфигурацию, она по умолчанию выключена.

## Автосохранение

Текст группируется по завершению поля (потеря фокуса), рубрика/массовая команда/список — отдельное законченное изменение. Каждый символ не отправляется. Валидация всей конфигурации выполняется до записи, включая пересечение двух списков рубрик. Сохранённый валидный JSON — действующий снимок; невалидная или ещё редактируемая строка остаётся локальным черновиком и не заменяет его. Поэтому отдельная колонка черновиков в базе не нужна.

Запросы одного окна сериализованы; при быстром выборе отправляется последнее ожидающее полное состояние. Проверяется ожидаемая ревизия. Потерянный ответ сверяется чтением; слепого повтора записи нет. Конфликт не переносит локальную ревизию на чужую: нужен явный выбор сохранённой версии. При выборе сервера предыдущий локальный вариант остаётся резервной копией в браузере.

Выключить фильтр можно даже с невалидным текстом: отдельно сохраняется выключатель поверх последней подтверждённой конфигурации, локальный ввод сохраняется. Включить с ошибочным полем нельзя. Тест и получение выборки не пишут материалы/связи.

Локальный черновик содержит только поля правил, ревизию и время, ключ ограничен origin/проектом/источником. Не содержит сообщений, ключей или RSS-выборки. Восстанавливается до 7 дней; это срок восстановления, не обещание фонового удаления. Ошибочный текст до размера HTML-поля также восстанавливается. Между портами/браузерами черновики не переносятся.

Внутренние ссылки и выбор проекта завершают запись; при ошибке показывается диалог приложения с возможностью оставить восстановимый черновик. Если localStorage недоступен, уход при ошибке блокируется. Закрытие окна/внешний переход с незавершёнными правками может вызвать системный диалог браузера. Browser Back/Forward, перезапуск/очистка браузера не могут гарантировать отсутствие системного диалога или сохранность localStorage. Серверные ошибки не показывают сырые ответы БД.

## Проверка до разрешения миграции

Из `CF-application/`:

`CF_RSS_FILTER_DEMO=1 CF_RSS_FILTER_ENABLED=0 CF_RSS_FILTER_CONFIG_ENABLED=1 .venv/bin/python -m uvicorn rss_filter_demo:app --host 127.0.0.1 --port 8007`

Открыть http://127.0.0.1:8007/studio . Демо использует прежние публичные снимки из /private/tmp; сохранения — только память процесса, после перезапуска сбрасываются. Есть список источников для проверки ухода/возврата; рабочих POST импорта/отправки/связей нет.

## Порядок рабочего подключения (выполнен)

1. Сверить рабочие данные/правила, закрыто сохранить исходные определения валидатора, защиты версии, функции импорта и конфигурации.
2. Применить именно проверенный `rss_filter_config.sql` через Supabase-плагин; проверить прежние данные и права. Не преобразовывать прежние правила автоматически.
3. Новый локальный `main:app`: `CF_LIBRARY_ENABLED=1 CF_RSS_FILTER_ENABLED=1 CF_RSS_FILTER_CONFIG_ENABLED=1`, DEMO=0, отправки и получатель выключены, .env не менять.
4. Рабочие правила и импорт владелец согласует отдельно. Демо-конфигурацию в рабочую базу не переносить. Включение нового интерфейса само по себе ничего не сохраняет.
