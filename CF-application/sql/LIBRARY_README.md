# Общая библиотека — CF-02C-009

`library.sql` — атомарная миграция, применена к рабочей Supabase 30.10.2026 по отдельному разрешению владельца: `20261030145533 cf_shared_sources_and_material_library`. Повторно её не запускать. Ниже сохранён порядок проверки для новых установок.

## Изменения

- Расширяет существующую `cf_sources`: тип, расположение, описание, результат последней успешной загрузки. Действующая RSS-лента остаётся с прежним UUID и кодом.
- Существующая `cf_materials` остаётся единственным хранилищем содержимого. Добавляется только признак `protected`, по умолчанию false.
- `cf_projects` — минимальный справочник, сейчас только реальный СССР (`cccp`). Управления другими проектами в интерфейсе нет.
- `cf_project_sources` — подключения, допуск отбора, буквальная фраза заголовка и заметки каждого проекта.
- `cf_project_materials` — ссылки на материалы без копирования. Начальное заполнение связывает все прежние материалы и источники установки с СССР.
- Четыре новые серверные функции: сохранение/подключение источника, атомарный импорт, отбор материалов, предварительный просмотр очистки. Новые таблицы закрыты RLS и недоступны анонимным и пользовательским API-ролям. Клиент service_role остаётся только на сервере.
- Посты, журнал публикаций, переписка, курсор Telegram и разрешения отправки не меняются.

## Порядок подключения после разрешения

1. Перед применением ещё раз проверить актуальную схему, количество и контрольные суммы существующих данных. Сохранить закрытую резервную копию источников, материалов, постов и журнальные контрольные суммы вне Git.
2. Применить `library.sql` единственной миграцией через Supabase-плагин. При ошибке транзакция откатывается целиком.
3. Сравнить прежние поля материалов (без нового protected) и постов/журналов, связи и количество записей. Ожидаемый исходный снимок 30.10.2026 — 1 источник, 98 материалов, 7 постов; перед применением пересчитать.
4. Только затем запустить локальный веб-сервер с `CF_LIBRARY_ENABLED=1`. Пример из каталога программы:

   `CF_LIBRARY_ENABLED=1 CF_INBOX_UI_ENABLED=1 CF_INBOX_RECEIVE_ENABLED=0 CF_INBOX_REPLY_ENABLED=0 CF_PUBLICATION_ENABLED=0 .venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000`

   Если порт занят — сначала согласовать остановку известного процесса либо использовать другой свободный порт. `.env` не менять. Это не запускает получателя Telegram.

5. Открыть `/studio/library/sources`, `/studio/cccp/sources`, `/studio/library/materials`, `/studio/cccp/materials`, `/studio/library/cleanup`. Проверить прежние посты и обращения только просмотром.
6. Получение RSS изменяет общую библиотеку. Проверять реальную запись отдельным оговорённым действием. Повтор ленты не создаёт копий и не перезаписывает существующее содержимое. Отбор в проект — отдельная кнопка; фильтр применяется по сохранённым настройкам. Отключение источника сохраняет ранее выбранные материалы.

## Ограничения

- Для сайта, БД, API, файла и другого типа сохраняются только расположение и несекретное описание; адаптеров нет. Пароли, ключи и токены в карточке не хранить.
- Лента регистрируется единожды по типу и адресу; домен приводится к нижнему регистру, фрагменты/данные авторизации в HTTP-адресах не допускаются. Разные URL зеркал автоматически не объединяются. Материал дедуплицируется по прежней паре `(source_id,url)`; межисточниковая похожесть текстов не определяется.
- Загрузка ручная, без расписания. Дата последнего успешного получения — не полноценный журнал ошибок. Старый `/import` при включённой библиотеке направлен в новый импорт существующей Ботанички.
- Отбор источника с выключенным допуском даёт 0 новых связей. Это настройка отбора, а не запрет общего получения или независимого ручного выбора конкретного материала.
- Просмотр очистки: возраст по `imported_at`, нет защиты, нет ни одной ссылки проекта или поста. Только список до 50 записей, без DELETE. Реального удаления и снятия защиты через интерфейс нет. Нельзя использовать этот снимок как разрешение на будущее удаление без повторной проверки.
- Публикации и переписка по-прежнему относятся к единственному рабочему проекту. Многопроектное редактирование постов не заявляется.
- При необходимости отключить новую часть — снять флаг `CF_LIBRARY_ENABLED`, схему и данные не удалять. Полный откат схемы отдельно проектируется; автоматического DROP нет.

## Проверено на рабочей базе 30.10.2026

Резервная копия исходных 1 источника / 98 материалов / 7 постов: `/private/tmp/cf-library-backup-20261030/before.json`, файл 600, папка 700, вне Git. Сразу после миграции прежние поля всех записей и контрольные суммы журналов/переписки совпали с исходными.

Из локального интерфейса выполнен один импорт первой страницы: 50 получено / 50 новых, всего 148 общих материалов. В проект автоматически ничего не добавилось (98 ссылок). Вручную выбран один материал об ивах: стало 99 ссылок проекта, общих материалов осталось 148. Копия материала не создавалась, пост не сохранялся.

Проверочный сервер оставлен на `http://127.0.0.1:8001/studio/library/materials` с включённой библиотекой и выключенными публикациями, ответами и получателем Telegram. Другой процесс на 8000 не останавливался; не путать эти экземпляры. `.env` не менялся. После нового запуска флаг библиотеки нужно передать явно, как в примере выше.

Просмотр очистки до 31.10.2026 UTC показал 49 неиспользуемых новых материалов. Это не решение об их удалении. Существующие материалы/посты и журналы не изменились. Создание других типов источников, работа нескольких синтетических проектов и сбои проверялись изолированно; лишних тестовых источников/проектов в рабочей базе нет.
