Проверены таблица, ссылки между двумя страницами, обратная ссылка и идентификаторы заголовков. После изменения только index.md отдельный HTTP-запрос вернул «Редакция 2. ОБНОВЛЕНИЕ ПРОВЕРЕНО» и изменённые ячейки «Посажены», «5»; «Редакция 1» отсутствовала.

**Пользовательская проверка:** владелец подтвердил первый просмотр словами «вижу страницу, она реагирует и открывает вторую страницу». Только после этого изменён Markdown. После предложения вручную обновить ту же страницу владелец подтвердил новую редакцию: «вижу». Обе контрольные точки соблюдены.

## Границы выдачи

Разрешён точный список URL: /, /index.md, /notes.md. Сервер не раздаёт каталог и собственный код. HTTP-проверка вернула 404 для /../AGENTS.md, /%2e%2e/AGENTS.md, /.env, /.git/config, /server.mjs, /index.md?x=1, /%69ndex.md. Содержимое реальных документов и секретов не читалось.

В коде дополнительно проверяются realpath, отсутствие символической ссылки и открытие через O_NOFOLLOW. Подмену файла символической ссылкой отдельным живым тестом не выполняли; это реализованная защита, а не результат такого испытания. Сырой HTML экранируется, ссылки допускаются только на два образца и якоря, изображения не загружаются. Политика CSP запрещает скрипты и внешние ресурсы. Полный аудит безопасности не проводился.

## Применимость и ограничения

Эксперимент доказал простой цикл: локальный Markdown → HTML по запросу → изменение Markdown → ручное обновление браузера → новая редакция. Два образца с таблицей и переходами работали рядом с чатом.

Для сотен файлов и приватного GitHub это только основа возможного решения. Получение приватных файлов, права доступа, синхронизация и разрешение конфликтов не реализованы и не проверены. Текущий сервер читает только локальные образцы; подключение GitHub не требуется для их просмотра. Нагрузка, большие документы, изображения, произвольные относительные ссылки, повторяющиеся заголовки и поиск не испытаны. Автоматического обновления и редактирования через браузер нет.

Импорт marked привязан к абсолютному пути библиотек среды Codex на этом Mac; перенос на другую машину потребует отдельно согласованной доступной зависимости. Разрешённые имена файлов заданы в коде. Это минимальный эксперимент, а не универсальный просмотрщик.

Владелец подтвердил первый просмотр и новую редакцию после изменения исходника и ручного обновления. Постоянные HTML-копии не нужны.

Для HTP можно рассмотреть отдельный эксперимент на небольшом согласованном наборе локальных документов с ограниченной выдачей файлов. Работа с сотнями документов, приватным GitHub, изображениями, поиском и сложными ссылками этим опытом не подтверждена. Нужны отдельные требования к синхронизации и доступу.
