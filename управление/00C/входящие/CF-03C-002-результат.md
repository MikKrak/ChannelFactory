## Применимость и ограничения

Эксперимент доказал простой цикл: локальный Markdown → HTML по запросу → изменение Markdown → ручное обновление браузера → новая редакция. Два образца с таблицей и переходами работали рядом с чатом.

Для сотен файлов и приватного GitHub это только основа возможного решения. Получение приватных файлов, права доступа, синхронизация и разрешение конфликтов не реализованы и не проверены. Текущий сервер читает только локальные образцы; подключение GitHub не требуется для их просмотра. Нагрузка, большие документы, изображения, произвольные относительные ссылки, повторяющиеся заголовки и поиск не испытаны. Автоматического обновления и редактирования через браузер нет.

Импорт marked привязан к абсолютному пути библиотек среды Codex на этом Mac; перенос на другую машину потребует отдельно согласованной доступной зависимости. Разрешённые имена файлов заданы в коде. Это минимальный эксперимент, а не универсальный просмотрщик.

### Поведение и настройки

Название заголовка-ссылки открывает подробный план отдельной страницей. Отдельная стрелка слева раскрывает его прямо под заголовком; повторное нажатие сворачивает. Дополнительная строка «Открыть план работ» убрана. Для этого Markdown содержит только стандартный заголовок со стандартной относительной ссылкой.

В разделах с заголовками «Содержание» и «Навигация» ссылки работают только как переходы. Названия этих разделов заданы в viewer-rules.json; переименование потребует согласованного изменения настроек. Во вложенном документе навигационные разделы скрываются, а при отдельном открытии документа остаются видимыми. Markdown при этом не переписывается.

Заголовок h1 синий (#2459b3), размер 1.7em; h2 зелёный (#287344), 1.3em; h3 зелёный, 1.1em. Во вложенном представлении размеры h1/h2 дополнительно уменьшены стилем сервера. Таким образом, основные пользовательские настройки вынесены в JSON, но часть базового оформления ещё остаётся в сервере.

Вложенные документы изначально закрыты. Содержимое подготавливается вместе со страницей, а не загружается по нажатию. Реализованы ограничение глубины (maxDepth=3) и остановка раскрытия повторного файла в текущей цепочке; отдельный полноценный тест сложного графа ссылок не проводился. Повторяющиеся заголовки и повторные включения одного файла могут требовать дальнейшей работы с уникальностью якорей.

### Вывод и границы

Подтверждена полезность одной системы документов: агент читает и правит стандартный Markdown, браузер показывает его с общим оформлением и вложенными планами. Общий файл сейчас служит кратким перечнем направлений, подробности живут в подпланах; агент должен явно читать связанные файлы, они не раскрываются ему автоматически.

Навигация по всему репозиторию пока только обсуждалась. Сервер разрешает три конкретных Markdown-файла одной экспериментальной папки; произвольные каталоги, ../, приватный GitHub, синхронизация, сотни документов и поиск не реализованы. Markdown-ссылки с относительными путями пригодны для связывания документов, но поддержку таких путей нашим сервером ещё нужно отдельно проектировать и проверять в разрешённой области.

Это экспериментальный результат, а не принятое решение о внедрении в ChannelFactory или HTP. Возможный следующий шаг для согласования: испытание ограниченного набора реальных документов с относительными путями и проверкой границ доступа. Самостоятельно этот этап не начат.
