# CF-02C-011 — Мастер настройки RSS-источника и фильтра проекта

- **Статус:** IN_PROGRESS
- **От:** 00C — Управление ChannelFactory
- **Кому:** 02C — Разработка
- **Основание:** решение владельца 31.10.2026: следующий этап — качественный отбор материалов в проект без LLM и без программирования пользователем. Общую переработку интерфейса временно отложить.

## Цель
Создать в существующем рабочем интерфейсе ChannelFactory универсальный инструмент, позволяющий обычному пользователю исследовать RSS-источник, настроить тематический фильтр **для конкретного проекта**, испытать его на реальных материалах и затем применять к новым материалам. Не писать специальный фильтр для «Ботанички» или проекта «СССР — Свой сад своими руками»: это только проверочный пример.

## Сценарий пользователя
1. Пользователь открывает источник и выбирает проект, для которого настраивает отбор.
2. Команда «Анализировать» показывает доступные поля RSS, рубрики/категории (если есть), примеры записей и распределение по рубрикам. При отсутствии рубрик интерфейс сообщает об этом и предлагает правила по тексту.
3. В понятных полях интерфейса пользователь задаёт включаемые и исключаемые рубрики, слова и словосочетания; видит, как эти условия сочетаются. Программировать выражения не требуется.
4. Команда «Проверить фильтр» на доступной выборке материалов показывает три результата: **подходит**, **не подходит**, **сомнительно**, а также конкретную причину решения. До подтверждения настройка не меняет материалы и связи проекта.
5. Пользователь корректирует правила, повторяет проверку и сохраняет фильтр. При последующем штатном получении RSS проект получает только материалы, прошедшие его правила. Сомнительные доступны для отдельного просмотра и не попадают автоматически в принятые материалы.
6. Общая библиотека хранит материалы независимо от фильтра конкретного проекта; один источник может иметь разные настройки для разных проектов.

## Требования к реализации
- **Без LLM, нейросетей, внешних AI API, скачивания моделей и дополнительных платных сервисов.** Использовать обычные алгоритмы, возможности RSS, обработку текста и статистику.
- Предусмотреть объяснимость и предсказуемость: показать, какое именно правило сработало, и не выдавать эвристику за понимание смысла текста.
- Разумно обрабатывать отсутствие рубрик, пустые описания, разные регистры и словоформы, совпадения в названиях и описаниях; выбрать простое расширяемое решение, не превращая задачу в исследование NLP.
- Правила хранятся как конфигурация связи **источник ↔ проект**, не как глобальный запрет для источника. Новые типы источников сейчас не реализовывать.
- Предварительная проверка на уже загруженных материалах должна быть безопасной, без автоматического перепривязывания, удаления и повторного импорта.
- Не смешивать тематический отбор с редакционной оценкой качества будущего поста.
- Встроить инструмент в существующий каркас интерфейса, без нового общего редизайна.
- Если для постоянного хранения правил или результатов необходима миграция Supabase, **подготовить её и изолированно проверить**, но не применять к рабочей базе без отдельного разрешения владельца. До разрешения демонстрировать на безопасных тестовых данных.
- Не выполнять реальные импорты, удаления, публикации, ответы читателям и изменения рабочих связей без отдельного разрешения.

## Приёмка
1. На примере реальной структуры RSS «Ботанички» пользователь через интерфейс видит, какие данные и рубрики доступны, без ручного изучения XML и без написания кода.
2. Через интерфейс можно создать, изменить, проверить и сохранить правила отбора для СССР; те же средства пригодны для другого RSS и другого проекта.
3. Предпросмотр показывает реальные заголовки и результат по каждому материалу с объяснением, включая «сомнительно»; изменение правил позволяет немедленно перепроверить выборку.
4. Подтверждено тестами, что при штатном импорте **в проект** автоматически привязываются только принятые фильтром материалы; отклонённые и сомнительные не исчезают из общей библиотеки. Текущие 99 связей проекта не изменены самовольно.
5. Прежние функции источников, общей библиотеки, материалов, постов и переписки не нарушены; автоматические внешние операции не запускались.
6. Отчёт в `управление/00C/входящие/`: что реализовано, как проверять через интерфейс, результаты тестов, ограничения алгоритма, изменения схемы/их статус, состояние рабочих данных и открытые вопросы.
