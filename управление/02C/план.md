# План 02C — Разработка

Обновлено: 30.10.2026.

## Сводка для 00C

- **Цель:** обращения читателей каналу и ручной ответ с сохранением переписки.
- **Состояние:** публикация проверена на канале; CF-02C-007 завершён реальным приёмом двух обращений. Следующий объём реализован локально по прямому поручению владельца: хранение, кабинет, ограниченный получатель и ручной ответ. Все 72 теста прошли.
- **Ближайший шаг:** приёмка [локальной переписки](../00C/входящие/02C-локальная-переписка-2026-10-30.md), контрольный коммит и согласование рабочего подключения.
- **Ограничения:** код обращений не закоммичен; SQL обращений в рабочую Supabase не применён, получение/ответы закрыты параметрами, реальная двусторонняя переписка ещё не испытана.

## Следующая контрольная точка

1. 00C принимает локальную реализацию; владелец сохраняет/синхронизирует код, фиксируется SHA. Базовый локальный HEAD при реализации: 0572d2c3c7566d33f62aacc7c7a90d6601112d3e.
2. Согласовать схему, резервное сохранение, рабочую миграцию, конфигурацию бота/чата и срок хранения персональных данных; исходные события пока сохраняются полностью, автоочистка не реализована.
3. Согласовать судьбу временного журнала и подтверждение ранее сохранённых диапазонов. Получатель не запускается веб-сервером; внешний потребитель должен быть исключён отдельно.
4. После подключения проверить кабинет на согласованных данных. Затем отдельно разрешить один просмотренный ответ конкретному читателю, сверить доставку и записи.

Подготовка ответа не отправляет его. Реальная отправка закрыта отдельным флагом и списком UUID ответов. Захват получателя не истекает автоматически; после аварии сначала остановить прежний процесс. Неизвестный результат отправки требует ручной сверки без автоматического повтора.

## Отложено и исключено

Навигатор исключён. Постоянный фоновый polling, webhook, ИИ-ответы, новые проекты/боты, рассылки, общий редизайн, production/Vercel и публичный доступ не развёрнуты. Вложения и редактирования событий сохраняются для разбора, но не считаются поддержанными текстовыми обращениями.

Программные файлы меняем локально; синхронизирует владелец. Документы — через GitHub-плагин. Секреты/.env, зависимости, публикационные разрешения и чужие таблицы этим этапом не менялись. Персональные данные в GitHub не размещать.
