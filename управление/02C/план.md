# План 02C — Разработка

**Текущая цель:** завершить подготовку уже перенесённого и проверенного локально прототипа, затем развернуть проверенную версию на Vercel из отдельной ветки `production`.

**Схема веток:** `main` — разработка и испытания на Mac; `production` — только проверенный выпуск для Vercel. Перенос `main` → `production` выполняется после согласования с владельцем. Не считать ветку созданной или Vercel настроенным до проверки.

## Что делаем по порядку
1. **Выполнено:** резервная копия сохранена, исходники перенесены в GitHub, локальный сервер и действия через интерфейс/Supabase проверены.
2. **Зависимости:** добавить `CF-application/requirements.txt` с проверенными версиями; `.venv` и `.env` в GitHub не помещать.
3. **Обмен изменениями:** завершить проверку GitHub → Mac и Mac → GitHub через GitHub Desktop.
4. **Ветки:** создать `production` от проверенного `main`; настроить Vercel Production Branch на `production` и проверить поведение Preview Deployments для `main`.
5. **Vercel:** после отдельного согласования развернуть из `production` проект с Root Directory `CF-application`, проверить зависимости, переменные окружения и защиту редакторских маршрутов.
6. **Supabase:** проверить чтение и запись тестовых данных через сервер. Не менять рабочие данные без разрешения.
7. **Telegram:** отдельно, после успешной серверной проверки, реализовать и испытать webhook; не публиковать в действующий канал автоматически.
8. **Отчёт:** записывать в `управление/00C/входящие/` проверенные результаты, ошибки, ссылки на коммиты и следующий шаг. Подтверждённые изменения состояния предлагать для `STATUS.md`.

## Когда работа завершена
Код в GitHub без секретов, новая локальная копия работает, обмен GitHub Desktop проверен, сервер открывается с защищённым редактором и читает/записывает тестовые данные в Supabase. Telegram — отдельная завершающая проверка после запуска сервера.

**Следующий шаг:** подготовить `requirements.txt` и проверить двустороннюю синхронизацию. Затем создать `production` и настроить Vercel; не выпускать изменения `main` автоматически.
