# План 01C — Концепция

**Текущая цель:** помочь проверить переезд работающей программы. Новые функции и большой пересмотр концепции пока отложены.

## Согласованный цикл разработки
`main` → испытания на Mac → решение владельца → перенос в `production` → Vercel. Изменения концепции и тестовые сценарии не должны считаться разрешением на автоматический выпуск.

## Что делаем
1. Использовать уже подготовленный список проверок и обновлённый `STATUS.md`: локальная программа после переноса работает, включая списки, страницы, черновики и Supabase.
2. Уточнить оставшиеся непроверенные сценарии перед Vercel; не повторять уже принятые локальные проверки без причины.
3. Отдельно указать действия, которые нельзя выполнять автоматически при проверке: публикация в действующий канал, ответы читателям, изменение рабочих данных без разрешения.
4. Передать 00C уточнения по оставшимся проверкам. Не менять программу и не объявлять неподтверждённые функции работающими.
5. После запуска на Vercel сравнить реальные результаты с этим списком; передать 00C найденные проблемы.

## Что считать результатом
Есть понятный список «действие пользователя → что должно произойти → как проверить», пригодный для проверки локальной и серверной версии. В нём нет требований создавать новые функции.

**Следующий шаг:** уточнить сценарии проверки серверной версии; новые продуктовые решения из первого отчёта пока не рассматриваем.
