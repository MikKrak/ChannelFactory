# План проекта ChannelFactory

**Текущая цель:** закончить перенос работающей программы с Mac в GitHub, проверить запуск на Mac и на тестовом сервере Vercel, проверить чтение и запись тестовых данных Supabase. До завершения этого этапа новые функции не планируем.

## Что сделано
- ChatGPT-проект ChannelFactory и чаты 00C, 01C, 02C созданы.
- Документы распределены по разделам `концепция/`, `разработка/`, `reference/`, организационные правила находятся в `управление/`.
- Первый анализ концепции 01C получен; план безопасного переноса 02C получен. Исходники перенесены в `CF-application/` и отправлены в GitHub; локальная программа успешно запущена и проверена через интерфейс, включая Supabase. Серверная версия не проверена.
- Работаем с GitHub напрямую через подключённый плагин, без обязательного Work.

## Актуальные планы трёх чатов
- [00C — Управление](00C/план.md): согласование шагов и приёмка результатов.
- [01C — Концепция](01C/план.md): список пользовательских проверок существующей программы.
- [02C — Разработка](02C/план.md): перенос исходников, проверка локальной и серверной версии.
- [Подробный технический порядок](../разработка/WORK_PLAN.md).

## Порядок работы
1. **Mac (выполнено):** сделана резервная копия, исходники перенесены в клон GitHub, локальная программа работает.
2. **GitHub (выполнено):** восемь файлов программы отправлены в `CF-application/`; секреты исключены.
3. **Локальный запуск:** программа и операции с Supabase проверены; отдельно завершить проверку обмена изменениями GitHub Desktop в обе стороны и добавить `requirements.txt`.
4. **Разделение веток:** создать `production` от проверенного состояния `main`; `main` использовать для разработки и испытаний на Mac. Переносить код в `production` только по решению владельца. Настроить Vercel на Production Branch `production`, проверить Preview Deployments.
5. **Vercel:** после проверки кода развернуть тестовую веб-версию из `production`, защитить редакторские маршруты.
6. **Supabase:** проверить чтение и запись тестовых данных с сервера.
7. **Telegram:** отдельная проверка webhook и входящего сообщения после запуска сервера.
8. **Итог:** обновить `STATUS.md` только подтверждёнными результатами, перечислить оставшиеся ограничения.

## Когда этап завершён
Есть работающий локальный и серверный экземпляры, исходники синхронизируются с GitHub, тестовые данные читаются и записываются, результаты проверок зафиксированы, у всех трёх чатов есть актуальный следующий шаг. Не считать перенос и развёртывание выполненными до реального испытания.

**Ближайшее действие:** добавить `requirements.txt`, завершить проверку синхронизации Mac ↔ GitHub; затем создать `production` и настроить Vercel без автоматического выпуска изменений `main`.
