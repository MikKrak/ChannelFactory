# Вертикальный обмен ChannelFactory

Основа адаптирована из организационного подхода HTP: **вниз — решения, приоритеты, планы и задания; вверх — результаты, факты, вопросы и предложения**.

## Участники

Родительский чат — `00C — Управление`; дочерние — `01C — Концепция`, `02C — Разработка` и `03C — Исследования`. Владелец утверждает существенные решения.

## Задания вниз

Родитель создаёт адресный Markdown-файл задания в рабочей папке дочернего направления (`управление/01C/задания/`, `управление/02C/задания/` или `управление/03C/задания/`) **когда появится первое задание**. Не создавать пустые папки заранее.

Минимальные поля: идентификатор, автор/получатель, цель, контекст и ссылки, границы полномочий, ожидаемый результат, критерий приёмки, статус. Статусы заданий: `OPEN`, `IN_PROGRESS`, `COMPLETE`, `CANCELLED`, `SUPERSEDED`.

**Очередь заданий:** при запуске исполнитель самостоятельно просматривает файлы своей папки `задания/`, выбирает самое раннее задание со статусом `OPEN` (по номеру/дате поступления) и переводит его в `IN_PROGRESS`. После выполнения записывает результат в `управление/00C/входящие/` и отмечает задание `COMPLETE`. `CANCELLED` и `SUPERSEDED` не выполнять. Если задача заблокирована, сообщить 00C и не переходить к следующей без решения 00C. Не выполнять одновременно несколько задач без явного приоритета от 00C.

Чат не просыпается от коммита. Владелец активирует его коротким сообщением: «Проверь свои задания в GitHub и приступай к работе». Номер и содержание задания передавать в чате не нужно.

## Результаты вверх

Исполнитель записывает адресное сообщение в `управление/00C/входящие/` (создать при первом сообщении), с указанием задания, результата, ссылок на изменения, проверки и вопросов. Управляющий разбирает входящие и после обработки может переносить их в `входящие/обработано/`. Не дублировать полный текст результата, если он уже сохранён в каноническом документе.

## Горизонтальное взаимодействие

Соседние чаты не назначают друг другу обязательных задач напрямую: межнаправленческие вопросы поднимаются в 00C. Предложения и результаты не становятся утверждёнными решениями автоматически.

## Состояние

Для активной роли при необходимости вести краткое `состояние.md`: текущая задача, подтверждённый результат, блокировки и следующий шаг, со ссылками на канонические документы. Не создавать дубликат общего плана.

## Пределы

Система GitHub не является автоматическим диспетчером чатов. Задание считается завершённым только после проверки результата; факт записи в GitHub не означает успешного теста программы.
