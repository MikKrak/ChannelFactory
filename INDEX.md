# Индекс проекта ChannelFactory

**Канонический репозиторий:** `MikKrak/ChannelFactory`, ветка `main`.

## С чего начинать

1. `AGENTS.md` — правила работы помощников, доступ к GitHub и безопасность.
2. `PROJECT_RULES.md` — организационные правила и порядок согласования.
3. `STATUS.md` — подтверждённое техническое состояние.
4. `концепция/CONCEPT.md` — согласованная концепция и открытые продуктовые вопросы.
5. `управление/план-проекта.md` — короткий общий план; у каждого чата свой план.

## Существующие документы

- `README.md` — назначение проекта и актуализированная карта репозитория.
- `разработка/DEVELOPMENT.md` — технические решения, гипотезы и исследования.
- `reference/PLAN.md` — история ранних экспериментов и расходов; старые следующие шаги не считать актуальными.
- `docs/NOTEBOOK_PROTOCOL.md` — существующий протокол совместного редактирования.
- `управление/план-проекта.md` — организационный план и ближайшие этапы.
- `управление/структура-чатов.md` — роли чатов.
- `управление/03C/план.md` — рабочая папка и краткий план 03C — Исследования.
- `управление/иерархический-обмен.md` — задания вниз, результаты вверх.

## Целевая организация (не равна текущему дереву файлов)

- `управление/` — координация, планы и обмен между чатами.
- `концепция/` — продуктовая модель и исследования (будущее распределение документов).
- `разработка/` — архитектура, спецификации и испытания (будущее распределение документов).
- `CF-application/` — действующий каталог исходников приложения. Для Vercel планируется Root Directory = `CF-application`, после проверки фактической структуры приложения.
- `reference/` — справочные материалы по мере появления потребности.

**Важно:** исходники перенесены, локальная программа проверена; Vercel не настроен. `main` — разработка, `production` — будущая ветка выпуска. `разработка/WORK_PLAN.md` — только архивная ссылка. Каноническое знание хранится в одном месте; индекс даёт ссылки, а не копии.
